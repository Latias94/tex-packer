# Migrating tex-packer-core from v0.2 to v0.3

v0.3 intentionally breaks the Rust API. It replaces mutable, representation-oriented types with validated configuration, explicit physical/logical identity, and workflow facades. CLI command families and the established JSON, plist, and template export shapes remain stable.

## Upgrade

Update all first-party crates together:

```toml
[dependencies]
tex-packer-core = "0.3"
```

Do not keep a v0.2 CLI or GUI linked to a v0.3 core crate.

## API Map

| v0.2 | v0.3 |
| --- | --- |
| `PackerConfig` | `PageConfig` plus `OfflineConfig` or `RuntimeConfig` |
| Mutable config fields or struct literals | Consuming builders with fallible `build()` |
| Separate family and heuristic fields | `PackingStrategy` or `RuntimeStrategy` variants containing only relevant options |
| Free `pack_images(inputs, config)` | `OfflinePacker::new(config).pack_images(inputs)` |
| Free `pack_layout(...)` | `OfflinePacker::pack_layout(Vec<LayoutItem>)` |
| `pack_layout_items(...)` | `OfflinePacker::pack_layout(...)` |
| `prelude::*` and broad root imports | Explicit imports from `config`, `model`, `offline`, `runtime`, `export`, and `error` |
| Public `Packer<K>` and concrete packers | Removed; select a strategy in validated workflow configuration |
| Generic `Atlas<K>` / `Frame<K>` | Owned string keys plus typed `PageId`, `RegionId`, and `FrameId` |
| Public `Atlas.pages` / `Page.frames` | `Atlas::pages()` / `Page::frames()` |
| `Frame.frame` and `Frame.rotated` | Resolve the frame, then read `ResolvedFrame::region().content()` and `.rotated()` |
| `OutputPage { page, rgba }` | `RenderedPage::page_id()` plus `rgba()` or `into_rgba()` |
| Direct `PackOutput` fields | `atlas()`, `pages()`, or `into_parts()` |
| Direct `Atlas` serde | `AtlasDocument::from_atlas` and `AtlasDocument::try_into_atlas` |
| Runtime strategy passed beside config | Strategy stored in a validated `RuntimeConfig` |
| Runtime append tuple/field access | Owned `RuntimePlacement` with typed accessors |
| Ambiguous used/total area | Explicit content, allocation, and page area metrics |

The only supported public modules are:

```rust
tex_packer_core::config
tex_packer_core::error
tex_packer_core::export
tex_packer_core::model
tex_packer_core::offline
tex_packer_core::runtime
```

Placement algorithms, geometry conversion, preparation, and compositing are private implementation details.

## Offline Packing

Before:

```rust,ignore
use tex_packer_core::prelude::*;

let config = PackerConfig::builder()
    .with_max_dimensions(1024, 1024)
    .allow_rotation(true)
    .build();
let output = pack_images(inputs, config)?;

for page in &output.pages {
    page.rgba.save(format!("atlas_{}.png", page.page.id))?;
}
```

After:

```rust
# use image::{DynamicImage, RgbaImage};
use tex_packer_core::config::{OfflineConfig, PageConfig};
use tex_packer_core::offline::{InputImage, OfflinePacker};

# fn example() -> tex_packer_core::Result<()> {
let page = PageConfig::builder()
    .max_dimensions(1024, 1024)
    .allow_rotation(true)
    .build()?;
let config = OfflineConfig::builder().page_config(page).build()?;
let packer = OfflinePacker::new(config);
# let inputs = vec![InputImage {
#     key: "hero".into(),
#     image: DynamicImage::ImageRgba8(RgbaImage::new(16, 16)),
# }];
let output = packer.pack_images(inputs)?;

for rendered in output.pages() {
    let page = output
        .atlas()
        .page(rendered.page_id())
        .expect("rendered page identity must resolve");
    assert_eq!(rendered.rgba().dimensions(), page.size());
}
# Ok(())
# }
```

Choose the operation according to the input contract:

- `pack_images` preprocesses decoded images, deduplicates identical prepared pixels, lays them out, and renders RGBA pages.
- `layout_images` performs the same decoded-image preprocessing and deduplication but returns only an `Atlas`.
- `pack_layout` trusts caller-provided sizes/source metadata and performs no pixel trimming or content deduplication.

## Configuration

Page geometry is validated once and shared:

```rust
use tex_packer_core::config::{
    MaxRectsHeuristic, OfflineConfig, PackingStrategy, PageConfig,
};

# fn example() -> tex_packer_core::Result<()> {
let page = PageConfig::builder()
    .max_dimensions(2048, 2048)
    .border_padding(2)
    .texture_padding(2)
    .texture_extrusion(1)
    .allow_rotation(true)
    .build()?;

let offline = OfflineConfig::builder()
    .page_config(page)
    .trim(true)
    .strategy(PackingStrategy::MaxRects {
        heuristic: MaxRectsHeuristic::BestAreaFit,
        reference: true,
    })
    .build()?;
# let _ = offline;
# Ok(())
# }
```

`PageConfig::build` rejects zero dimensions, border exhaustion, impossible padding/extrusion reservations, and arithmetic overflow. `OfflineConfig::build` validates offline page-sizing policy and normalizes Auto budgets. Runtime configuration cannot contain trimming, sorting, or Auto policy.

## Region and Frame Model

v0.2 put physical atlas geometry directly on every logical frame. v0.3 separates the facts:

- `Region` is one physical allocation. It owns content geometry, reserved allocation geometry, and rotation.
- `Frame` is one logical sprite. It owns `FrameId`, the user key, source reconstruction metadata, and a `RegionId` reference.
- `Page` validates both collections and builds private identity indexes.

Use resolved traversal when a consumer needs both sides:

```rust
# use tex_packer_core::model::Atlas;
# fn inspect(atlas: &Atlas) {
for page in atlas.pages() {
    for resolved in page.resolved_frames() {
        let frame = resolved.frame();
        let region = resolved.region();
        println!(
            "{}: frame {}, region {}, content {:?}, rotated {}",
            frame.key(),
            frame.id(),
            region.id(),
            region.content(),
            region.rotated()
        );
    }
}
# }
```

IDs are opaque values, not positions in a vector. Use `Atlas::page`, `Page::region`, and `Page::frame` rather than indexing by `id.get()`.

## Duplicate Keys

Offline keys are labels, not identity. Repeated keys receive distinct `FrameId` values and remain ordered.

- Native v2 documents, JSON array, and template projections preserve both logical entries.
- JSON hash cannot represent repeated object keys; insertion order is deterministic and the later value wins.
- Plist keeps its v0.2 dictionary shape and emits entries in deterministic order, but property-list dictionaries cannot expose repeated keys as distinct identities. Duplicate-key behavior is parser-dependent and therefore lossy.
- Runtime keys remain unique. A duplicate append returns `TexPackerError::DuplicateKey` without mutating the session.

Consumers that need lossless offline identity must store `PageId` plus `FrameId`, not a key-to-frame map.

## Runtime Packing

Before:

```rust,ignore
let mut session = AtlasSession::new(config, RuntimeStrategy::Guillotine);
let (page, frame) = session.append("hero".into(), 64, 32)?;
```

After:

```rust
use tex_packer_core::config::{
    GuillotineChoice, GuillotineSplit, PageConfig, RuntimeConfig, RuntimeStrategy,
};
use tex_packer_core::runtime::AtlasSession;

# fn example() -> tex_packer_core::Result<()> {
let page = PageConfig::builder().max_dimensions(1024, 1024).build()?;
let config = RuntimeConfig::builder()
    .page_config(page)
    .strategy(RuntimeStrategy::Guillotine {
        choice: GuillotineChoice::BestAreaFit,
        split: GuillotineSplit::SplitShorterLeftoverAxis,
    })
    .build()?;
let mut session = AtlasSession::new(config);

let placement = session.append("hero".into(), 64, 32)?;
println!(
    "page {}, frame {}, allocation {:?}",
    placement.page_id(),
    placement.frame_id(),
    placement.allocation()
);
assert!(session.evict_by_key("hero"));
# Ok(())
# }
```

`AtlasSession::append` and `RuntimeAtlas::append_with_image` now prepare every fallible operation before commit. A rejected append does not consume IDs, mutate allocator state, add records, or partially write pixels.

## Persistence and Export Schemas

`Atlas` deliberately does not implement `Serialize` or `Deserialize`. It contains runtime indexes and must always satisfy aggregate invariants.

```rust
# use tex_packer_core::model::Atlas;
use tex_packer_core::model::AtlasDocument;

# fn persist(atlas: &Atlas) -> Result<(), Box<dyn std::error::Error>> {
let document = AtlasDocument::from_atlas(atlas);
let encoded = serde_json::to_string(&document)?;
let decoded: AtlasDocument = serde_json::from_str(&encoded)?;
let restored = decoded.try_into_atlas()?;
assert_eq!(&restored, atlas);
# Ok(())
# }
```

`AtlasDocument` uses native schema version 2, rejects unknown wire fields, and validates identities, references, geometry, overlap, and metadata before producing an `Atlas`. Its structural schema is [`../../schemas/tex-packer-atlas-document-v2.schema.json`](../../schemas/tex-packer-atlas-document-v2.schema.json).

The legacy exporters are separate projections. Their metadata remains schema version `"1"`, and their established field shapes are unchanged.

## Statistics

Map old metrics according to the question being asked:

| Old intent | v0.3 metric |
| --- | --- |
| Unique sprite pixel area | `content_area` |
| Space reserved including padding/extrusion | `allocation_area` |
| Total final atlas area | `page_area` |
| Pixel-content occupancy | `content_occupancy` |
| Allocator-space occupancy | `allocation_occupancy` |
| Deduplicated logical entries | `num_aliases` |

Physical area counts each region once. Runtime statistics use the same equations and add allocator fragmentation fields.

## CLI YAML Changes

The flat CLI/YAML field names remain stable, but parsing is stricter:

- Unknown and duplicate fields are errors.
- YAML tags are errors.
- YAML merge keys (`<<`) are errors; they are not expanded.
- YAML 1.1-only boolean words remain strings and fail for boolean fields.

Use `tex-packer pack <input> --config config.yaml --print-config` to validate and inspect the merged projection.

## Dependency Changes

- `serde_yaml 0.9` was replaced by `serde_yaml_ng 0.10`.
- `rand 0.8` moved to `rand 0.10.2`; callers should use `RngExt`, `random`, `random_range`, and `random_bool` where applicable.
- Criterion moved from 0.7 to 0.8.2.
- indicatif moved from 0.17 to 0.18.6.
- egui/eframe/egui_extras 0.35 and rfd 0.17 are intentionally deferred to a separate GUI/platform migration.

## Upgrade Checklist

1. Replace `PackerConfig` with validated page and workflow configs.
2. Replace free functions with `OfflinePacker` or runtime facade methods.
3. Replace field access with accessors and resolved-frame traversal.
4. Replace key-based offline identity with typed IDs where duplicates matter.
5. Replace direct `Atlas` serde with `AtlasDocument`.
6. Select the correct content or allocation statistics.
7. Run exporter golden tests if downstream tooling consumes legacy formats.
8. Update all tex-packer crates to 0.3 together.
